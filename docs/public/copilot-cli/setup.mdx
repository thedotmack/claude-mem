# Copilot CLI Setup

> **Give GitHub Copilot CLI persistent memory across sessions.**

[GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-hooks) runs lifecycle hooks from `~/.copilot/hooks/*.json`. Claude-mem installs those hooks so tool use is captured, compressed into observations, and injected at the next session start — plus an MCP server for search.

<Info>
**How it works:** The installer writes `~/.copilot/hooks/claude-mem.json` (`exec` + `args`, no shell) and registers the MCP server in `~/.copilot/mcp-config.json` (and the legacy `~/.github/copilot/mcp.json` path). Copilot CLI has no transcript JSONL; capture is stdin JSON from hook events.
</Info>

<Note>
Copilot CLI is the **host**, not the observer model. Observations are still generated by the worker's configured provider (Claude / Gemini / OpenRouter / CMEM Pro).
</Note>

## Prerequisites

- [GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/set-up/install-copilot-cli) (`copilot`) on `PATH`
- [Node.js](https://nodejs.org/) 20+
- Bun (auto-installed by `npx claude-mem install` if missing)

## Installation

```bash
npx claude-mem install --ide copilot-cli
```

The installer will:

1. Detect Copilot CLI (`copilot` on `PATH`)
2. Write user-level hooks to `~/.copilot/hooks/claude-mem.json`
3. Register the MCP server in `~/.copilot/mcp-config.json` and `~/.github/copilot/mcp.json`
4. Start the worker service

`--ide` is a single host. A second IDE is a second install command.

Restart Copilot CLI after install — hook files are loaded at startup.

## What gets captured

| Copilot CLI event | Internal event | Purpose |
|-------------------|----------------|---------|
| **sessionStart** | `context` | Injects memory context into the session |
| **userPromptSubmitted** | `session-init` | Records the user prompt and opens a session |
| **postToolUse** | `observation` | Queues successful tool results for the observer |
| **postToolUseFailure** | `observation` | Queues failed tool results |
| **sessionEnd** | `summarize` | Asks the observer to summarize the session |

Hook commands use Copilot CLI's `exec`/`args` form (no shell) and run with `cwd` set to your home directory so a deleted worker cwd cannot break Claude CLI probes.

The adapter accepts camelCase Copilot payloads (`toolName`, `toolArgs`, `toolResult.textResultForLlm`) and snake_case aliases.

## Verify

```bash
npx claude-mem status
python3 -m json.tool ~/.copilot/hooks/claude-mem.json
```

Open the worker URL printed on startup (default [http://127.0.0.1:37700](http://127.0.0.1:37700)). After a Copilot CLI turn that uses tools, the viewer should show **PROMPT** cards and, once the observer runs, **observation** cards — not only copied chat.

## Troubleshooting

### Only prompts appear, no observations

1. Confirm the worker is healthy: `npx claude-mem status`
2. Confirm Claude CLI (or your chosen provider) can run. If logs say `Claude executable not found`, set `CLAUDE_CODE_PATH` in `~/.claude-mem/settings.json` to the real binary (not a mise shim that needs a valid cwd).
3. Restart Copilot CLI so it reloads `~/.copilot/hooks/`.
4. Use a prompt that actually calls tools (`bash`, `view`, …). `sessionStart` / `userPromptSubmitted` only store prompts.

### Hooks not firing

1. File must be version `1` JSON under `~/.copilot/hooks/` (or `$COPILOT_HOME/hooks/`).
2. Restart Copilot CLI after editing hooks.
3. Re-run `npx claude-mem install --ide copilot-cli`.

### Worker not running

```bash
npx claude-mem status
npx claude-mem logs
npx claude-mem restart
```

## Uninstalling

```bash
npx claude-mem uninstall
```

This deletes `~/.copilot/hooks/claude-mem.json` and leaves other hook files and MCP servers intact. `~/.claude-mem` data is preserved.
