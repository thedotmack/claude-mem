---
title: Haystack
description: Retrieve a selected project observation in a native Haystack pipeline and explicitly preserve a useful result.
---

Add local project memory to a Haystack pipeline through the existing Claude-Mem
MCP server. The
[runnable example](https://github.com/thedotmack/claude-mem/tree/main/examples/haystack)
uses `MCPToolset` for memory calls and a native `ProjectMemory` component for
retrieval. A caller can explicitly save a useful decision, then retrieve its
index, surrounding timeline and full details in a later pipeline run.

This integration supports explicit saves and on-demand recall. It does not
capture conversations or automatically inject context. It requires no model
API key, deepset account or CMEM Pro subscription for the local demonstration.

## Requirements

Verified on Linux with Python 3.12.9, Node.js 24.22.1, Claude-Mem 15.16.1,
`haystack-ai` 3.5.0, `mcp-haystack` 2.1.1 and `mcp` 2.3.0. Use Python 3.11
or newer for these Haystack packages. macOS, Windows and deepset-hosted
deployments have not been verified by this example.

The implementation uses Haystack's official
[`MCPToolset`](https://docs.haystack.deepset.ai/docs/mcptoolset) and
[custom component](https://docs.haystack.deepset.ai/docs/custom-components)
APIs. The component exposes typed `index`, `timeline` and `details` outputs,
and `Pipeline.run` routes the project, query and selected observation ID to it.
No additional adapter package or document store is needed.

## Connect

First [install Claude-Mem](/installation) and start its local worker:

```bash
npx claude-mem start
npx claude-mem status
```

Copy `examples/haystack` from the repository into your local application and
install the pinned dependencies in a virtual environment:

```bash
cd examples/haystack
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
```

Set the absolute path to the installed MCP server. For the default Claude Code
marketplace installation on macOS or Linux:

```bash
export CLAUDE_MEM_MCP_SERVER="$HOME/.claude/plugins/marketplaces/thedotmack/plugin/scripts/mcp-server.cjs"
export HAYSTACK_TELEMETRY_ENABLED=false
```

For a different installation location, use its `plugin/scripts/mcp-server.cjs`.
If the worker uses `CLAUDE_MEM_DATA_DIR` or `CLAUDE_MEM_WORKER_PORT`, set the
same values in this shell. The example passes its environment to the subprocess.
It supplies the script as one Node process argument, including when the path
contains spaces.

`MCPToolset` loads only `save_memory`, `search`, `timeline` and
`get_observations`. Each operation closes the toolset in `finally`; the example
does not start the worker or modify host configuration. Haystack telemetry is
disabled by default in this example unless the caller has explicitly set its
telemetry environment variable.

## Preserve a result and retrieve it through the pipeline

Choose an explicit project name and a decision worth keeping:

```bash
python memory_pipeline.py save checkout-service "Haystack release decision" "Use the violet region for the retrieval service."
```

After the worker acknowledges the save, the command prints
`Saved memory #<id>: Haystack release decision.`. Use that ID in a separate
process to run the retrieval pipeline, replacing `123` below:

```bash
python memory_pipeline.py recall checkout-service "Haystack release decision" 123
```

The pipeline prints a compact search index, the selected observation's timeline,
and its full details. The details should contain the violet-region decision.
A known observation can still be retrieved when newer notes have pushed it
outside the current search page; the selected project remains attached to both
follow-up reads.

In an application, add `ProjectMemory()` with
`pipeline.add_component("project_memory", ProjectMemory())` and supply its
`project`, `query` and `observation_id` inputs through `Pipeline.run`.
Connect its `details` output to a later component only when that context is
relevant. Choose the project in application code and treat recalled text as
reference material rather than instructions to invoke tools or change accounts.

## Identity and privacy

Every memory call carries the chosen project. Saves are attributed to
`platformSource: haystack` and use the existing manual memory session for that
project and platform. The pipeline does not create observer sessions or install
capture hooks. Project filters select an account's own records; they do not
authenticate different users. Each account should use its own authorized worker.

The save helper hashes the exact project, title and text into a
`sourceFingerprint`. Repeating the same input returns the already saved ID;
changing the input produces a distinct note. This identifier does not encrypt
the stored note. Transport retries are disabled with `max_retries=0`.

Explicit notes are stored as supplied. This example does not process transcript
privacy tags or automatically exclude a directory, so choose nonsecret text
before calling `save`. The worker's own indexing, sync and export settings still
apply. If a later pipeline component sends retrieved text to a model, that
model provider also receives it.

## Failures and troubleshooting

Tool discovery and individual invocations have ten-second timeouts. A stopped
or unresponsive worker, invalid input, or a project/ID mismatch produces a
nonzero CLI exit instead of a successful result. The native tool layer reports
`ToolInvocationError`; a failed pipeline component is reported through
Haystack's `PipelineRuntimeError`.

Check `npx claude-mem status`, the absolute script path, and matching worker
port/data-directory settings. If a save times out, the worker might have
committed it before the client stopped waiting. Repeat the same project,
title and text to reuse the write identity.

The verified workflow uses a native Haystack pipeline and real MCP calls without
model generation. It does not validate a model provider, a hosted deployment,
or an automatic chat-history capture flow.

## Verify and disconnect

Run the live checks against a disposable worker. Set
`CLAUDE_MEM_MCP_SERVER`, `CLAUDE_MEM_WORKER_PORT` and `CLAUDE_MEM_DATA_DIR` to
its script, port and data directory, then run from the example directory:

```bash
python -m unittest discover -s . -v
```

The five tests use the real Haystack packages, bundled MCP server and SQLite
worker. They check repeated saves, cross-client pipeline recall, project
filtering, platform attribution, a known note older than the search page,
script paths containing spaces, native validation errors, a refused connection
and an unresponsive worker. They leave harmless notes in uniquely named test
projects in the disposable database for inspection.

To disconnect, stop using the component and remove the example's virtual
environment or dependencies from your application. No host configuration needs
restoring. Existing memory stays in Claude-Mem; delete demonstration notes
separately through the viewer if they are no longer needed.
