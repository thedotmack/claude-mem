title: Kiro
description: Explicit memory save and project-scoped recall using Kiro's MCP support.

Kiro IDE can use Claude-Mem's existing stdio MCP server. This guide covers explicit save, search and selected observation retrieval. It adds no automatic capture and no context injection. It runs locally and needs no CMEM Pro plan. Kiro's own login and plan are still needed for chat. Kiro CLI was not tested.

Tested on macOS with Kiro IDE 1.3.0 and Node 22. Official references: [MCP configuration](https://kiro.dev/docs/mcp/configuration/) and [MCP overview](https://kiro.dev/docs/mcp/).

## Connect

1. Add this entry to `~/.kiro/settings/mcp.json`. Replace both paths with absolute paths on your machine. Get the first with `which node`:

```json
{
  "mcpServers": {
    "claude-mem": {
      "command": "/absolute/path/to/node",
      "args": ["/absolute/path/to/claude-mem/plugin/scripts/mcp-server.cjs"]
    }
  }
}
```

Kiro starts as a desktop app and may not have your shell `PATH` (for example with nvm), so use absolute paths. Keep other servers in the file. Choose a different name if you already have an unrelated server named `claude-mem`.

2. If Kiro was open when you saved the file, run **Developer: Reload Window**. Kiro does not always pick up a new `mcp.json` while it runs.
3. Check the "Kiro - MCP Logs" output. It should show `[claude-mem] Connected`.

The MCP server starts the Claude-Mem worker by itself if it is not running. A workspace `.kiro/settings/mcp.json` is merged with the user file and wins over it.

If the worker runs somewhere else, add `"env": {"CLAUDE_MEM_WORKER_URL": "http://127.0.0.1:PORT"}` to the entry. Auto-start is then off, and a stopped worker gives a tool error. Use literal values in `env`, not `${VAR}`: Kiro asks for extra approval to expand variables.

## Save and recall

Ask Kiro, for example: `Use claude-mem save_memory to save "Restore must reject snapshots missing required tables." with project "memory-practice". Return the saved ID.`

Kiro asks for approval on each tool call. Review each one, and do not add `save_memory` to `autoApprove`. In a later chat, request `search` with query `restore` and project `memory-practice`, then `get_observations` with selected IDs and that same project. Inspect actual tool results rather than trusting a final assistant claim.

Project arguments restrict the query; they are not a multi-user authorization boundary. This local MCP connection can access tools and data available to the worker owner. Do not expose it to untrusted users.

Always pass `project`. Kiro starts this server outside your project folder, so a save without `project` goes to `unknown-project`, and `CLAUDE_MEM_EXCLUDED_PROJECTS` cannot match your checkout.

## Verification and disconnect

With current Claude-Mem bundles built, run:

```bash
NODE_BIN=/absolute/path/to/node BUN_BIN=/absolute/path/to/bun \
  python3 tests/fixtures/kiro-smoke.py
```

The fixture reads the entry from this page and runs it over stdio, with a space in its paths and a temporary database. It checks save receipts, stored text, scoped search and details, a foreign-project ID being withheld, auto-start of a stopped worker, and a tool error when auto-start is off (`CLAUDE_MEM_WORKER_AUTOSTART=false` or `CLAUDE_MEM_WORKER_URL`). It uses synthetic records only. It does not drive Kiro itself. Windows and Linux were not tested.

If nothing happens after you save `mcp.json`, run **Developer: Reload Window**. If the chat still cannot use the tools, set `"kiroAgent.configureMCP": "Enabled"` in Kiro settings and reload again. If a tool fails, check the "Kiro - MCP Logs" output.

To disconnect, delete the `claude-mem` key from `mcp.json`, or set `"disabled": true` on it. Saved memories remain in the worker. No Claude Code configuration is changed.
