# OpenAI-Compatible Provider

Claude-mem can run observation extraction against any endpoint that speaks the
OpenAI `/chat/completions` shape. Set `CLAUDE_MEM_PROVIDER` to
`openai-compatible`, pick a preset (or supply a base URL), and memory runs
entirely off your Claude plan.

<Note>
**claude-mem observer**: choosing the claude-mem observer during
`npx claude-mem install` runs memory off-plan with nothing to configure. This
page is for bringing your own endpoint and key.
</Note>

## Why this is separate from the OpenRouter provider

`CLAUDE_MEM_OPENROUTER_BASE_URL` already lets the OpenRouter client talk to any
OpenAI-compatible endpoint, and it keeps working — nothing on that path changed.
But it carries three things that belong to openrouter.ai specifically:

- **Attribution headers.** `HTTP-Referer` and `X-Title` are sent to whatever
  host the base URL names, so pointing it at NVIDIA announces claude-mem's
  OpenRouter identity to NVIDIA.
- **`usage: { include: true }`**, gated on the URL containing `openrouter.ai`.
- **The cmem.ai gateway's credential-pinning rules**, which decide when a
  persisted base URL pins a persisted key. Those rules exist so an
  account-delivered gateway credential is never sent somewhere else — correct,
  and irrelevant to an endpoint you configured yourself, but you still share
  the same three settings keys with them.

This provider has its own settings keys. The request body is `model`,
`messages`, `temperature`, `max_tokens`, and `reasoning: { enabled: false }`
by default, so a reasoning model cannot spend the output cap thinking and
return an empty observation. Set `CLAUDE_MEM_OPENAI_COMPAT_REASONING` to `on`
to leave observer reasoning to the endpoint. To request a specific effort on
observer and API-agent calls, set `CLAUDE_MEM_OPENAI_COMPAT_REASONING_EFFORT`.
For example, set it to `high` to send `{"reasoning_effort":"high"}`. Choose a
value the model supports. OpenCode Go's `beam-free` lists `low` through `max`
and can continue reasoning when sent `none`. A strict server that rejects
the reasoning field as unknown gets the request once more without it. `max_tokens`
is `CLAUDE_MEM_OBSERVER_MAX_OUTPUT_TOKENS` (4096 by default); a model that only
accepts `max_completion_tokens` gets the request again with that field.

A claude-mem observer key (`cm_pro_…`) is never sent to these endpoints. Use the
key the endpoint issued.

## Quick start: NVIDIA NIM

<Steps>
<Step title="Get a key">
Sign in at [build.nvidia.com](https://build.nvidia.com) and create an API key.
It starts with `nvapi-`. NVIDIA's hosted models are free to start, which suits
observation extraction: it is high-volume and structured, and does not need a
frontier model.
</Step>

<Step title="Point claude-mem at it">
Set the endpoint preset and key in `~/.claude-mem/settings.json`:

```json
{
  "CLAUDE_MEM_PROVIDER": "openai-compatible",
  "CLAUDE_MEM_OPENAI_COMPAT_PRESET": "nvidia-nim",
  "CLAUDE_MEM_OPENAI_COMPAT_API_KEY": "nvapi-..."
}
```

Or keep the key out of `settings.json` and put it in `~/.claude-mem/.env`:

```
OPENAI_COMPAT_API_KEY=nvapi-...
```
</Step>

<Step title="Pick a model (optional)">
The preset defaults to a small, fast NVIDIA-served model. Any model id from
build.nvidia.com works and is passed verbatim:

```json
{ "CLAUDE_MEM_OPENAI_COMPAT_MODEL": "nvidia/nemotron-3-super-120b-a12b" }
```
</Step>

<Step title="Restart the worker">
```bash
npx claude-mem restart
```
</Step>
</Steps>

## Rapid-MLX

[Rapid-MLX](https://github.com/raullenchai/Rapid-MLX) runs locally on Apple
Silicon. Start the server:

```bash
rapid-mlx serve qwen3.5-4b-4bit --port 8000
```

Get the loaded model id from `http://localhost:8000/v1/models` and set it in
`~/.claude-mem/settings.json`:

```json
{
  "CLAUDE_MEM_PROVIDER": "openai-compatible",
  "CLAUDE_MEM_OPENAI_COMPAT_PRESET": "rapidmlx",
  "CLAUDE_MEM_OPENAI_COMPAT_MODEL": "mlx-community/Qwen3.5-4B-MLX-4bit"
}
```

No API key is required by default. The preset uses `http://localhost:8000/v1`,
the same default port as vLLM. Restart the worker after changing settings.

## Settings

| Setting | Default | Description |
|---------|---------|-------------|
| `CLAUDE_MEM_PROVIDER` | `claude` | Set to `openai-compatible` to select this provider |
| `CLAUDE_MEM_OPENAI_COMPAT_PRESET` | `''` (= `custom`) | Named endpoint preset from the table above. Settings file or environment only |
| `CLAUDE_MEM_OPENAI_COMPAT_BASE_URL` | preset's | OpenAI-compatible base URL. `/chat/completions` is appended if absent. Settings file or environment only |
| `CLAUDE_MEM_OPENAI_COMPAT_MODEL` | preset's | Explicit model id; takes precedence over a host-configured model |
| `CLAUDE_MEM_OPENAI_COMPAT_DEFAULT_MODEL` | empty | Overrides the whole implicit default chain (last-served model, then the preset default). Empty keeps the existing chain unchanged; `none` removes both; any other id replaces both and is passed verbatim. An explicit `CLAUDE_MEM_OPENAI_COMPAT_MODEL` still wins. Settings file, environment or viewer |
| `CLAUDE_MEM_OPENAI_COMPAT_MODEL_FROM_SESSION` | `false` | Opt-in: only when exactly `'true'` does the observer use the model selected in the host session. Otherwise `CLAUDE_MEM_OPENAI_COMPAT_MODEL` then the preset default applies, as before. The gate is worker-side; the plugin still transports the session's model id either way. The id is sent as-is, without the host's provider, so the observer endpoint must serve the model the host session uses. When the endpoint answers a model-specific 404, or a 400 or 422 carrying a structured model-not-found refusal for that id, the observer logs one warning, stops using that id and goes back to the configured model; restart the worker once the endpoint serves it. |
| `CLAUDE_MEM_OPENAI_COMPAT_MODEL_FROM_HOST` | `false` | `'true'` reads the host OpenCode model for observation and summary requests. The value read is the literal `model` key from the host configuration file, not the effective default set by a CLI flag or by `ctx.model.default()` in V2; per-session model selection is handled by a separate opt-in. Explicit `CLAUDE_MEM_OPENAI_COMPAT_MODEL` (and `CLAUDE_MEM_TIER_SUMMARY_MODEL` for the small tier) wins; host ids are translated, and an unmapped id falls back to the preset's default model with one warning. Only a model declared under `provider.<id>.models` in `opencode.json(c)` can be translated; a built-in provider's model is not declared there, so it falls back the same way. The translated id is the host provider's, so that provider must be the same service as the observer endpoint: when the endpoint answers a model-specific 404, or a 400 or 422 carrying a structured model-not-found refusal, for it, the observer logs one warning, stops using that id and goes back to the configured model until the worker restarts. Settings file or environment only |
| `CLAUDE_MEM_OPENAI_COMPAT_OBSERVATION_BATCH_SIZE` | `1` | Queued tool events per observer request (1–32); see [Observation batching](#observation-batching) |
| `CLAUDE_MEM_OPENAI_COMPAT_REASONING` | `''` (= off) | `off` asks the observer to disable reasoning using the preset’s wire format. `on` leaves it to the endpoint |
| `CLAUDE_MEM_OPENAI_COMPAT_REASONING_EFFORT` | empty | Optional `none`, `low`, `medium`, `high`, `xhigh`, or `max`. An explicit value overrides the observer toggle and the API agent’s preset default. Empty keeps their existing behavior |
| `CLAUDE_MEM_OPENAI_COMPAT_API_KEY` | `''` | API key. Also read from `OPENAI_COMPAT_API_KEY` in `~/.claude-mem/.env` |
| `CLAUDE_MEM_OPENAI_COMPAT_API_KEYS` | `''` | Extra keys for rotation — see [multi-key rotation](/usage/multi-key-rotation) |

An unknown preset id degrades to `custom` rather than failing, because settings
are read during status polling and a typo should not crash a poll.

The viewer's **Settings → Advanced** panel edits the provider and model, and
displays the endpoint preset and base URL read-only. Set the preset and base URL
in `~/.claude-mem/settings.json` or environment variables with the same names.
They determine where requests and stored API keys are sent, so the settings
HTTP API cannot change them. An unrelated viewer save preserves those values.
The API key is set in `~/.claude-mem/settings.json` or `~/.claude-mem/.env` only.

## Observation batching

If tool events arrive faster than a local observer can process them, opt into
batching in `~/.claude-mem/settings.json`:

```json
{
  "CLAUDE_MEM_PROVIDER": "openai-compatible",
  "CLAUDE_MEM_OPENAI_COMPAT_OBSERVATION_BATCH_SIZE": "4"
}
```

Keep your existing endpoint and model settings. An environment variable with the
same name overrides the file. The default is `1`; values outside the integer
range 1–32 use that default. This setting applies only to `openai-compatible`.
Claude and Codex retain their own batch settings, and Gemini/OpenRouter are
unchanged.

The observer takes up to that many events already waiting in the session's queue,
without waiting to fill a batch. A different prompt number, agent ID/type, working
directory, or a summary request ends the batch. Appended events must fit within
twice the model's per-field character cap (32,000 characters at most, lower for
small context windows). A large event that needs condensation waits for its own
turn. The first event still uses the normal field-condensation path; the batching
budget does not further truncate it or bound the entire conversation history.

For example, eight small queued events in the same context can use two requests
with a batch size of four instead of eight requests. The model may combine
related findings, so batching does not guarantee identical summaries. As with
Claude/Codex batching, returned observations share the batch's file evidence and
attribution. The existing invalid-output policy applies to the whole batch: one
retry, then discard if the reply is still invalid. Transport/quota failures and
cancellation do not confirm the claimed events as processed.

## MiniMax

`minimax` is MiniMax's global endpoint and `minimax-cn` the mainland-China one;
use the preset that matches where your account lives. Both default to
`MiniMax-M3`. Any model id MiniMax serves is passed verbatim, including legacy
ids such as `MiniMax-M2.7`.

To use M3.1 Flash instead, set its model id explicitly. The observer sends
`reasoning: { enabled: false }` by default, so Flash does not run its adaptive
thinking at `max` effort on every observation. Set
`CLAUDE_MEM_OPENAI_COMPAT_REASONING` to `on` to leave thinking to MiniMax.
Flash may also need a MiniMax Token Plan rather than pay-as-you-go. See the
[MiniMax OpenAI API reference](https://platform.minimax.io/docs/api-reference/text-openai-api).

```json
{
  "CLAUDE_MEM_PROVIDER": "openai-compatible",
  "CLAUDE_MEM_OPENAI_COMPAT_PRESET": "minimax",
  "CLAUDE_MEM_OPENAI_COMPAT_API_KEY": "<key from platform.minimax.io>",
  "CLAUDE_MEM_OPENAI_COMPAT_MODEL": "MiniMax-M3.1-Flash"
}
```

Reasoning models such as the M2 family can open their reply with a
`<think>…</think>` block. claude-mem removes a leading block like that on every
preset (it also covers DeepSeek R1 or Qwen3 on Ollama and vLLM), so the reasoning
is never stored or re-sent with the next request.

## iFlytek Spark

`iflytek` points at iFlytek's Astron MaaS platform and defaults to `spark-x2.5`.
Keys come from the [MaaS console](https://maas.xfyun.cn). The preset's base URL
is the pay-as-you-go endpoint; a Token Plan key is only accepted on the Token
Plan endpoint, so set the base URL as well:

```json
{
  "CLAUDE_MEM_PROVIDER": "openai-compatible",
  "CLAUDE_MEM_OPENAI_COMPAT_PRESET": "iflytek",
  "CLAUDE_MEM_OPENAI_COMPAT_API_KEY": "<your MaaS key>",
  "CLAUDE_MEM_OPENAI_COMPAT_BASE_URL": "https://maas-token-api.cn-huabei-1.xf-yun.com/v2"
}
```

A key used on the other endpoint is rejected with a 403 (`11200`). `spark-x2.5`
returns its reasoning in a separate `reasoning_content` field, which claude-mem
ignores, so only the answer is stored.

### When a key is required

Setting `CLAUDE_MEM_OPENAI_COMPAT_BASE_URL` replaces the preset's endpoint, so
whether a key is needed is decided by the endpoint you pointed at, not by the
preset name you started from:

| Endpoint | Key required |
|----------|--------------|
| `localhost`, `127.0.0.1`, `[::1]`, `*.local` | No |
| A private network address (`10.x`, `192.168.x`, `172.16–31.x`) | No |
| Anything else | Yes |

Without an override, the preset decides — the hosted presets need a key, the
local ones do not.

A remote endpoint that genuinely needs no authentication still works: set
`CLAUDE_MEM_OPENAI_COMPAT_API_KEY` to any non-empty value. The default errs
toward asking for a key because the alternative is a provider that reports
itself ready and then fails every observation with a 401.

```json
  "CLAUDE_MEM_PROVIDER": "openai-compatible",
```


Alternatively, store the key as `OPENAI_COMPAT_API_KEY` in
`~/.claude-mem/.env`. Restart the worker after changing the configuration.
Without a model or key, this provider is unconfigured and dispatch falls
through to Claude.

## Troubleshooting

**Memory silently runs on Claude instead.** Dispatch falls through to Claude
when the provider is selected but not fully configured — a missing base URL, a
missing model, or a missing key on a preset that needs one. That fall-through is
deliberate: a half-configured endpoint should not fail every observation. Check
`npx claude-mem doctor`.

**404 from the endpoint.** Almost always a wrong base URL or a model the
endpoint does not serve; the error names both settings. Note that some gateways
prefix model ids differently from the vendor's own docs.

**Repeated timeouts.** Requests are streamed, so a request is given up only
after 90 seconds with no token and no keep-alive from the endpoint, or after
300 seconds in total. A self-hosted endpoint that queues requests behind a load
balancer spends that queue wait silent, so the wait reads as idle; raise
`CLAUDE_MEM_LLM_STREAM_IDLE_TIMEOUT_MS` past it. `CLAUDE_MEM_LLM_TIMEOUT_MS`
does not apply to streamed requests; it is the deadline only for an endpoint
that refuses streaming (a 400 naming `stream` or `stream_options`), which
claude-mem then calls non-streamed for the rest of the worker's life. If
requests keep timing out, prefer a small, fast model: observation extraction is
a high-volume structured task, not a reasoning benchmark.

**Empty or cut-off observations.** A model that will not hold to the output
schema produces nothing usable. Small instruct-tuned models generally do better
here than reasoning models, whose thinking output tends to crowd out the
structured reply. When the log says a reply was cut off at the output-token
limit, raise `CLAUDE_MEM_OBSERVER_MAX_OUTPUT_TOKENS`.
