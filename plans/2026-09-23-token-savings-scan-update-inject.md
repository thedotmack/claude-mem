## Executive summary (read this first)

The funnel we want is: **plugin update → agent runs a scan → user sees labeled savings vs their status quo → if not on Pro, a trial offer sized to how they already work.**

PR #4212 puts the "run the scan" steer into `plugin/scripts/version-check.js`. Phase 0 shows that channel does not reach the model on any host today, and the branch it hooks into usually does not fire after a real marketplace update. Details and citations are in Phase 0. So this plan **keeps the skill idea, rewrites the skill text, and moves the steer** to the one place that already delivers model-visible text on every hooks-based host: the SessionStart context handler (`src/cli/handlers/context.ts`). That handler already has a "show a notice exactly once" marker pattern and a Pro trial copy module we can copy from.

What ships if Alex greens:

1. A rewritten `plugin/skills/token-savings-scan/SKILL.md` that scans `~/.claude-mem/settings.json`, compares to a small opinionated target, quotes only labeled claims that exist in this repo, and offers the existing 30-day trial link with a new attribution tag. No invented fields, no invented percentages, no bucket tables.
2. A once-per-version upgrade notice in the SessionStart handler: when the running plugin version differs from the last version this machine saw, prepend two lines to the injected context steering the agent to the skill, then remember the version. Gated by one new settings key. Copies the `pro-fallback-notice.marker` pattern.
3. Tests, docs rows, and the skill id added to the telemetry allowlist so `skill_invoked` counts it.

`version-check.js` stays untouched. Soft OAuth, paid infra, SyncHub, and any force-merge of #4212 are out of scope.

## Decision: where the steer lives

**Recommendation: SessionStart context handler, once per new version, not `version-check.js`.**

Why, in one breath each:

- It is the only path that reaches the model on Claude Code, Codex, and Cowork today (0.2).
- `version-check.js` output is exit-0 stderr on Claude Code (not model-visible per docs), unreachable on Codex, and its "upgraded" branch usually does not fire after a marketplace update because the new cache dir has no marker (0.1).
- A once-only marker pattern already exists two lines above where we would add ours (0.2).
- The trial URL builder already exists; we add one attribution value (0.3).

What "once" means here: the notice fires when `~/.claude-mem/upgrade-notice.version` exists **and** holds a different version than the running bundle. It then overwrites the file. A fresh install has no file: we write it silently and show nothing, because the welcome hint already covers first sessions (0.2). Net effect: one notice per upgrade, per machine, never on first install, never repeating.

Risks called out (Alex should read these):

1. **SessionStart noise.** Codex has a tight hook-output budget and the context is already trimmed to 10,000 chars (`src/services/context/ContextBudget.ts:9`). The notice is capped at two lines and prepended, same as the fallback notice. It fires once per upgrade, so the steady-state cost is zero.
2. **Claim honesty.** The skill quotes only rows from table 0.4, each with its label. Three numbers in #4212 have no source in this repo and are removed (0.4 last row). The "Session ~10–15%" line is removed unless Alex supplies a source; see Green checklist.
3. **Trial copy.** Never "see how long your trial will last". No pricing or dollar figures in the terminal (matches `install.ts:1147-1151`). Trial length comes from `PRO_TRIAL_DAYS`; the 7/14/30 experiment inconsistency is flagged, not resolved here.
4. **Pro users still get the steer.** The steer is neutral ("run the scan"). The skill, not the steer, decides whether to offer the trial, using the settings in 0.3. Existing promos do not check Pro status at all; this plan does not fix those.
5. **Agent may ignore the steer.** `additionalContext` is a hint, not a command (Claude Code docs, 0.1). The skill is also user-invocable as `/claude-mem:token-savings-scan`, so the funnel has a manual path.
6. **Cursor gets nothing.** Hook output does not reach the Cursor model. Out of scope; noted for a later phase.
