# Toolkit — Implementation Plan (2026-10-02)

## Goal

Every day, claude-mem finds the **series of tool calls** that agents repeated successfully **more than 5 times**. It automatically turns each series into one reusable, parameterized script and puts the scripts in the **Toolkit**. Agents reach the Toolkit through:

- a generated `toolkit` skill
- a `claude-mem toolkit` CLI
- worker HTTP routes
- the MCP tools `toolkit_search` and `toolkit_show`

## Decisions (approved by Alex, 2026-10-02 — do not re-litigate)

- Name: **Toolkit**.
- Runs **daily**, **automatically**, with **no human approval step**.
- Unit = an ordered **series of tool calls** (any tool) from one agent's run. It is NOT a single shell command or a fragment of one.
- Threshold: a series qualifies when it occurred **more than 5 times** (`count > 5`).
- Only count occurrences whose steps **succeeded**.
- **Merge near-duplicate series** into one tool so the toolkit stays small.
- Skip series containing steps a plain script can't run (MCP connector calls, WebSearch, Agent/subagents, ToolSearch, …). Log them as skipped.
- Destructive series (`rm -rf`, force push, `reset --hard`, `DROP`, …) are **saved but never go live**.
- Scope: a series seen in 2+ projects is global; otherwise it belongs to its one project.
- Background reading (research only; this plan supersedes its phasing): Notion "Toolkit API — Research Brief (2026-09-25)" https://app.notion.com/p/3e8771da7f4d818680b5ec62cbc58f08

- Do NOT use `SettingsDefaultsManager.get()` to read user settings. Use `loadFromFile`.
- Do NOT use `queryToolUses` for mining (500-row cap). Do NOT `SELECT tool_response` for all rows: payloads reach 64 KB × 56k rows. Compute what you need in SQL (`json_extract`, the success expression), and fetch full payloads by id only for the ≤8 sample occurrences per tool.

- Do NOT import the frozen `CLAUDE_CONFIG_DIR` / `DEFAULT_CLAUDE_CONFIG_DIR` constants from `src/shared/paths.ts`.
- Do NOT pass an `AbortSignal` into HTTP providers' `query()`: doing so sets `maxRetries: 0` (`OpenRouterProvider.ts:838`). The deadline signal is for the Claude SDK path only.
- Do NOT add a worker route that executes scripts. Execution happens in the CLI process, in the user's cwd. The worker can be bound to `0.0.0.0`, which would make a run route remote code execution.
- Do NOT invent provider methods. Read `ClaudeProvider.ts:819-915` and `OpenAICompatibleProvider.ts:161-213` first and copy their shapes.
- Do NOT use `redactText` from error-scrub for tool data. It truncates at 8 KB and collapses paths.
- Do NOT run `npm run build-and-sync` or `npm publish`, do NOT push anything except the working branch, and do NOT touch the user's live worker (port 37701).

## Phase 2 — The miner (deterministic; no LLM)

All new files live in `src/services/toolkit/`. The miner is pure TypeScript over a `Database`.

### What to implement

1. **`src/shared/shell-segments.ts`** (new). Move the private `splitSegments` (and its `shell-quote` import) out of `src/cli/adapters/codex-file-context.ts:3, 13-34` into this exported module. Import it back into `codex-file-context.ts` so there's no behavior change.
2. **`src/services/toolkit/step-signature.ts`**: `toStepSignature(toolName: string, toolInput: {command?: string; url?: string}): string | null`.
   - **Bash** (also Codex `exec_command` `cmd`; see `shellCommandOf` at `src/services/worker/http/shared.ts:67-72`):
     - Replace heredoc bodies first: `/<<-?\s*['"]?(\w+)['"]?[\s\S]*?\n\1\b/g` → `<<HEREDOC`, keeping a copy of each body for the import fingerprint below.
     - Split with `splitSegments`. For each segment:
       - Drop leading `NAME=value` tokens.
       - Unwrap the wrappers `rtk`, `env`, `time`, `nohup`, `command`.
       - Take the binary's basename (`/usr/bin/git` → `git`).
       - If the binary is in `SUBCOMMAND_BINARIES = git gh npm npx pnpm yarn bun bunx docker kubectl vercel wrangler notebooklm claude codex uv pip pip3 brew supabase stripe fly cargo go`, append the first non-flag token. For `gh`, also append the second non-flag token (`gh pr view`). For `npm`/`bun` `run`, append `run` only.
       - Inline interpreters (`python`/`python3 -` or `-c`, `node -e`/`-`, `bun -e`) become `python3[<sorted imported modules>]`. Get the modules from `import x`, `from x import`, `require('x')` and `from 'x'`, found in the heredoc body or the `-c` string.
     - Drop glue heads entirely: `cd echo printf true : sleep set export test [ pwd`.
     - Collapse consecutive identical segment heads into `head+`.
     - Join the heads with `+`. If nothing is left, return `null`: the step is ignored.
     - Result: `Bash:git status+git diff`.
   - **Read/Write/Edit/Grep/Glob/NotebookEdit:** the tool name.
   - **WebFetch:** `WebFetch:<hostname>` (plain `WebFetch` if the URL is invalid).
   - **Anything else:** the tool name, including full `mcp__…` names.
3. **`src/services/toolkit/destructive-commands.ts`**: `classifyDestructiveCommand(text: string): { destructive: boolean; rule?: string }`. Use a named regex list:
   - `rm -rf` / `rm -fr` / `rm -r -f`
   - `git push --force|-f|--force-with-lease`
   - `git reset --hard`, `git clean -f…`, `git branch -D`, `git checkout -- .`
   - `DROP (TABLE|DATABASE|SCHEMA)`, `DELETE FROM`, `TRUNCATE`
   - `npm unpublish`, `gh repo delete`, `gh release delete`, `kubectl delete`, `docker system prune`, `vercel (rm|remove)`, `wrangler delete`
   - `mkfs`, `dd … of=/dev/`, `chmod -R 777`
4. **`src/services/toolkit/series-miner.ts`**: `mineToolkitSeries(db: Database, settings): MiningResult`.
   - **Read** with one SQL query, ordered by `content_session_id, COALESCE(agent_id,''), created_at_epoch, id`. Select `id, content_session_id, agent_id, project, cwd, tool_name, json_extract(tool_input,'$.command') AS command, json_extract(tool_input,'$.cmd') AS cmd, json_extract(tool_input,'$.url') AS url`, plus a computed `succeeded` column (see below).
     - For rows whose `tool_input` is invalid JSON (truncated), fall back: `command` is null, and a Bash row with a null command is ignored.
   - **`succeeded`** is the discovery rule, copied as one SQL expression. Truncated rows fall back to `LIKE`:
     ```sql
     NOT (tool_name='WebFetch' AND json_valid(tool_response) AND CAST(json_extract(tool_response,'$.code') AS INTEGER) >= 300)
     AND NOT (tool_name='SendMessage' AND json_valid(tool_response) AND json_extract(tool_response,'$.success') = 0)
     AND NOT (json_valid(tool_response) AND json_type(tool_response)='text' AND json_extract(tool_response,'$') LIKE 'Error:%')
     AND NOT (tool_name='Bash' AND json_valid(tool_response) AND (json_extract(tool_response,'$.interrupted')=1 OR json_type(tool_response,'$.backgroundTaskId') IS NOT NULL))
     AND NOT (tool_name='Bash' AND NOT json_valid(tool_response) AND (tool_response LIKE '%"backgroundTaskId"%' OR tool_response LIKE '%"interrupted":true%'))
     AND NOT (tool_name='Agent' AND json_valid(tool_response) AND json_extract(tool_response,'$.status')='async_launched')
     ```
   - **Privacy, re-applied at read time:** drop rows where
     - `isProjectExcluded(cwd || project, settings.CLAUDE_MEM_EXCLUDED_PROJECTS)`,
     - the tool is in `settings.CLAUDE_MEM_SKIP_TOOLS` (comma list, parsed like `shared.ts:132-135`),
     - `isRecursiveMemoryTool(tool_name)` is true, or
     - the tool name contains `toolkit_`.
   - **Streams:** group rows by `(content_session_id, agent_id ?? '')`. Map each row to a step `{signature, succeeded, rowIds:[id]}`; skip rows whose signature is `null`. Collapse consecutive identical signatures: a run of length ≥2 becomes `signature+`, its `succeeded` is the AND of the run, and its `rowIds` are concatenated.
   - **N-grams:** for each stream and each `n` in 2..8, slide a window. A window counts **only if every step succeeded**. For each series key (step signatures joined with ` → `), accumulate:
     - `occurrenceCount`
     - the set of sessions
     - the set of projects
     - the most recent 8 occurrences, each as `{contentSessionId, project, rowIds}`
   - **Qualify:** `occurrenceCount > TOOLKIT_MINIMUM_OCCURRENCES_EXCLUSIVE` (constant `= 5`, with a comment quoting the rule "more than 5 times").
   - **Scriptability:** `SCRIPTABLE_TOOLS = Bash Read Write Edit Grep Glob WebFetch`. Match on the tool-name prefix of each step signature. Qualifying series that contain any other tool go to `skipped` with `{signature, reason: 'unscriptable:<tools>'}`. Do this **before** the maximal filter, so an unscriptable super-series never hides a scriptable sub-series.
   - **Maximal filter** (scriptable set only): discard series `S` when a longer qualifying series `T` contains `S` as a contiguous sub-sequence and `count(T) >= SUBSERIES_ABSORPTION_RATIO (0.8) × count(S)`.
   - **Near-duplicate merge:** union-find over the remaining series. Two series join the same group when their **step-level Levenshtein distance ≤ 1**. The primary member is the highest count, then the longer, then lexicographically first. A group's totals are:
     - `occurrenceCount` = sum of member counts
     - `sessionCount` = size of the union of sessions
     - `projects` = union of projects
     - samples = the primary's 6 most recent occurrences plus up to 2 from other members
   - **Scope:** `projects.length >= 2` → `scope:'global', project:null`; else `scope:'project', project:projects[0]`.
   - **Output:** `{ candidates: MinedToolCandidate[]; skipped: {signature, reason}[]; stats: {rowsRead, streams, qualifyingSeries, scriptable, groups} }`.
