# e5-пилот: multilingual-e5-small vs FTS на реальных данных

Дата прогона: 2026-07-31. Офлайн-пилот по `plans/2026-07-29-e5-embedding-migration.md` —
продакшн не тронут, БД открыта только readonly, Chroma не использовался,
индекс — numpy npz. Все файлы пилота: `scripts/memory-eval/pilot/`.

## Установка эксперимента

- **Запросы**: 200 пар из `scripts/memory-eval/gold.json` (no-judge, gold = session-linkage).
  Та же метрика и тот же gold, что у baseline-харнесса — сравнение яблоки-к-яблокам.
- **FTS baseline**: тот самый код харнесса — `ftsPool` (пул 50, project-scoped) →
  `rankPool('recency')` → top-5 (`measure.ts` переиспользует `lib/retrieve.ts` без копий).
- **e5**: `intfloat/multilingual-e5-small`, `normalize_embeddings=True`, top-5 по косинусной
  близости среди активных observations того же проекта (`project = ? OR merged_into_project = ?` —
  та же область поиска, что у FTS). Два варианта: без префиксов (MVP по плану) и с
  `query:`/`passage:` (фаза 2 плана).
- **Кандидаты**: 6681 активных observations + 138 активных semantic_facts. Факты экспортированы
  и заэмбежены (для будущего использования), но в ранжировании не участвуют: gold-ids — это
  observation ids, и FTS-baseline ранжирует только observations.
- **Текст observation для эмбединга**: title + narrative + facts + concepts.

## Главные цифры (hit-rate@5)

| подход | все (n=200) | русские (n=194) | английские (n=6) |
| --- | --- | --- | --- |
| FTS (recency, код харнесса) | 17.5% | 17.0% | 33.3% |
| e5 без префиксов (MVP) | **28.5%** | **27.8%** | 50.0% |
| e5 с `query:`/`passage:` | 25.5% | 24.7% | 50.0% |

Разница e5-plain − FTS: **+11.0 п.п. в среднем, +10.8 п.п. на русских**.

Язык запроса — эвристика по кириллице в promptText. Выборка английских запросов
крошечная (n=6), цифры по EN шумные, выводы делаем по русским и среднему.

Пересечение top-5 (среднее число общих ids из 5):

| пара | overlap |
| --- | --- |
| FTS vs e5-plain | 0.064 (≈0.3 id из 5) |
| FTS vs e5-prefixed | 0.061 |
| e5-plain vs e5-prefixed | 0.68 |

FTS и e5 почти не пересекаются — это два принципиально разных ранкера
(лексика+recency против семантики), а не вариации одного.

Попарно по запросам (e5-plain vs FTS): e5 выиграл 36 запросов, проиграл 14,
в остальных 150 — одинаковый исход.

## Замечание о baseline

Исторический baseline харнесса — 21.0% (отчёт `16-48-11-301Z-eval`, снят в момент
сборки gold). Повторный замер тем же кодом на момент пилота даёт **17.5%**: БД живая,
за это время добавились observations, пулы и ранги сместились. Сравнение в таблице
выше честное — FTS и e5 измерены в одном прогоне на одних данных.

## Примеры

### Где e5 выиграл (e5 нашёл gold, FTS — нет), 5 из 36

1. `#4203` (ru): «Напиши точные ссылки на источники, там нужно юрл» — FTS-пул вообще
   пустой (0 кандидатов), e5 вытащил наблюдения сессии (7701, 7698 в top-5).
2. `#4215` (ru): «Да братишка, погнали! Потом решим вопрос с claude-mem и нашим
   claude-mem-dev, хорошо?» — почти нет значимых лексических термов; FTS вернул просто
   свежие наблюдения проекта, e5 нашёл 7505/7506 из gold.
3. `#4209` (ru): «Так блять она как будто каждое сообщение видит по отдельности…» —
   разговорная формулировка без ключевых слов домена; семантика сработала, лексика — нет.
4. `#4208` (ru): «Братишка, что-то не то! Я не готов каждую правку такую тупую по
   отдельности отлавливать…» — e5 нашёл 7690 из gold, FTS ушёл в нерелевантную свежесть.
5. `#4212` (en): «What the evidence supports. The literature's convergences…» — длинный
   аналитический текст; FTS после стоп-слов/MAX_TERMS промахнулся, e5 нашёл 7673/7678/7561.

Типичный паттерн побед: разговорные русские запросы без точных ключевых слов —
e5 ловит смысл, FTS деградирует до «пустой пул» или «просто свежие записи проекта».

### Где e5 проиграл (FTS нашёл gold, e5 — нет), 3 из 14

1. `#4160` (ru): «…а не вариков его dns там поправить или еще что-то?» — FTS поймал
   точное совпадение термина «dns» (7504, 7503 в top-5), e5 дал семантически близкие,
   но из других сессий.
2. `#4127` (ru): «…нашел Paypal у меня есть зарегистрированный…» — редкий термин
   «paypal»: лексическое совпадение точнее семантики (FTS: 7683, 7681 — оба gold).
3. `#4103` (ru): путь к файлу `'/Users/renat/Downloads/Запись экрана — ….mov'` —
   FTS матчится по токенам пути, для e5 это шум.

Типичный паттерн проигрышей: запросы с редким точным термином (dns, paypal, путь к
файлу) — там лексика сильнее. Это аргумент за **гибрид**, а не за замену FTS на e5.

## Проверка фазы 2 (префиксы)

Префиксы `query:`/`passage:` не помогли, а навредили: 25.5% против 28.5% без
префиксов (−3.0 п.п., overlap между вариантами 0.68). Для MVP по плану (без префиксов)
это зелёный свет: деградации без префиксов на наших данных нет — наоборот, plain лучше.
Фазу 2 (prefix wrapper) можно не делать.

## Стоимость воспроизведения

- Модель `intfloat/multilingual-e5-small`: **476 МБ** (HF cache,
  `~/.cache/huggingface/hub/models--intfloat--multilingual-e5-small`).
- Python-зависимости (эфемерный uv env, `uv run --with sentence-transformers`):
  torch **71.0 МиБ**, scipy 19.9 МиБ, transformers 10.6 МиБ, scikit-learn 7.9 МиБ +
  мелочь — итого ~**120 МиБ** скачивания (41 пакет; на macOS arm64 torch-wheel
  компактный, не гигабайтный linux-вариант).
- Индекс: `embeddings.npz` — **20 МБ** (6819 векторов × 384 dim × 2 варианта, float32).
- Время: эмбеддинг 6819 кандидатов ≈ 3.5 мин на CPU (два прогона — plain и prefixed),
  ранжирование 200 запросов — секунды.
- Сбой и обход: первая попытка скачивания модели зависла на 0 байт — huggingface_hub
  ушёл в hf-xet протокол, который виснет за здешним прокси. Лечится
  `HF_HUB_DISABLE_XET=1` (после этого ~0.5 МБ/с, ~16 мин на модель). Если миграция
  состоится, это стоит зафиксировать в доке установки.

## Вердикт

Порог решения: **+10 п.п. на русских или +5 п.п. в среднем**.

Факт: **+10.8 п.п. на русских, +11.0 п.п. в среднем** — оба порога пройдены.

**Миграция по `plans/2026-07-29-e5-embedding-migration.md` оправдана** — в варианте
MVP без префиксов (префиксы на реальных данных дают −3 п.п.). Учитывая почти нулевой
overlap с FTS и разные паттерны побед/поражений, целевая конфигурация — гибрид
(e5 ∪ FTS), а не чистая замена: e5 закрывает разговорные/бесключевые запросы, FTS —
редкие точные термины.

### Оговорки

- Gold = session-linkage (no-judge): харнесс меряет «находит ли поиск материал той же
  сессии», session-linked observations созданы после промпта. Оба подхода измерены в
  одинаковых условиях, поэтому сравнение валидно, но абсолютные цифры не стоит читать
  как «качество поиска» в вакууме.
- EN-подвыборка n=6 — шум.
- БД живая: цифры воспроизводимы на текущем снапшоте (`observations.jsonl`,
  `embeddings.npz`, `e5-top5.json`, `pilot-results.json` — все артефакты сохранены).

## Файлы пилота

- `export.ts` — экспорт кандидатов из прод-БД (readonly) → `observations.jsonl` (12 МБ).
- `embed.py` — e5-эмбеддинги + top-5 по gold → `embeddings.npz` (20 МБ), `e5-top5.json`.
  Кэш npz: повторный прогон без `--force` перевикторивает только запросы.
- `measure.ts` — FTS-baseline кодом харнесса + метрики/разбивки/overlap → `pilot-results.json`.
- Воспроизведение:
  ```bash
  bun scripts/memory-eval/pilot/export.ts
  HF_HUB_DISABLE_XET=1 uv run --with sentence-transformers scripts/memory-eval/pilot/embed.py
  bun scripts/memory-eval/pilot/measure.ts
  ```
